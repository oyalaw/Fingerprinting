AI Fingerprinting Label-Blind Proxy
Schema version 1.2

Purpose
-------
The proxy is an inline TCP byte-stream forwarder placed between the experiment
client and the real server.

Client -> Proxy -> Real Server

The proxy does not terminate TLS, decrypt payloads, parse the AI application
protocol, or receive AI ground-truth labels.

Configuration
-------------
experiment:
  experiment_id: EXP_PROXY_001
  output_dir: proxy_results
  existing_output_policy: error

proxy:
  listen_host: 0.0.0.0
  listen_port: 5000
  upstream_host: 10.42.0.195
  upstream_port: 5000
  connect_timeout_sec: 30
  buffer_size: 65536
  forwarding_log_enabled: false

capture:
  enabled: true
  interface: wlan0
  client_discovery_mode: automatic
  client_ips: []
  # Optional/manual override. Neutral trace IDs are generated when omitted.
  # For new FL runs, prepare_fingerprinting_dataset.py resolves the actual client_id
  # automatically from network-registration ground truth.
  client_aliases: {}
  strict_client_isolation: true
  per_client_artifacts: true
  snaplen_bytes: 256
  offload_management:
    enabled: true
    required: true
    allow_sudo_noninteractive: true
    restore_on_exit: true
    features: [gro, gso, tso, lro]
  extract_after: true
  burst_gap_sec: 0.05
  idle_threshold_sec: 0.5
  window_seconds: 5.0

Label blindness
---------------
The proxy configuration intentionally excludes AI/workload labels such as:
framework, runtime, task, deployment, family, architecture, variant,
application, dataset, and device.

Client IPs and optional aliases are network/session grouping metadata. They are
used to isolate a client-facing trace and are removed from classifier-ready
packet sequences. If aliases are supplied for federated experiments, use the
exact federated client_id values so the dataset builder can join each proxy
trace to the correct client ground truth.

Capture isolation
-----------------
An inline application proxy creates two TCP legs:

client <-> proxy
proxy <-> real server

Capturing both legs duplicates the same application byte stream. In automatic
discovery mode, client IPs do not need to be known before capture. With the
default topology, the archival and live BPF is:

host 10.42.0.1 and port 8080 and not host 10.42.0.195

The proxy then discovers actual participating client IPs from accepted
connections (and the live metadata stream), assigns neutral trace aliases, and
uses those discovered IPs for post-capture per-client isolation. Endpoint
identity is never included in classifier-safe predictor rows.

For a restricted diagnostic run, set client_discovery_mode: manual and provide
client_ips explicitly; the legacy host allow-list BPF is retained.

Multi-client artifacts
----------------------
The proxy retains one combined raw trace for audit and automatically generates
separate classifier-safe artifacts for each discovered/configured client:

<experiment_id>__<client_alias>_fingerprint_sequence.csv
<experiment_id>__<client_alias>_features.csv

For multi-client experiments, use these per-client files for classifier input.
The combined multi-client safe sequence is retained for audit/aggregate traffic
analysis and is marked classifier-ineligible in the manifest.

Windowing
---------
By default, feature extraction uses the multiscale set 0.5, 1, 2, and 5 seconds
plus an overall row. `window_seconds` is retained for legacy/single-scale
compatibility. All windows from the same independent experiment must remain in
the same train/validation/test group.

TCP flags
---------
SYN, ACK, FIN, and RST are derived from the authoritative tcp.flags bitmask.
This avoids tshark-version differences where tcp.flags.syn/tcp.flags.ack fields
may be blank or zero despite tcp.flags containing the bits.



Forwarding diagnostics size
---------------------------
The proxy summary always records aggregate bytes and connection/chunk counts.
`proxy.forwarding_log_enabled` defaults to false because recv() chunk boundaries
are not network packet boundaries and the per-chunk CSV can become very large.
Set it to true only for proxy implementation diagnostics.

PCAP size control
-----------------
The proxy defaults to capture.snaplen_bytes=256. dumpcap/tshark stores only the
first 256 bytes of each frame, while the PCAP record retains the original frame
length used by frame.len. This substantially reduces PCAP size because the
fingerprinting pipeline does not require encrypted payload contents. Set the
value to 0 to store full frames. A small snap length can reduce the completeness
of deep payload dissectors such as TLS reassembly, so increase it if full TLS
record reconstruction is a required experimental feature.

Packet offload fidelity protection
----------------------------------
By default the proxy actively manages capture-affecting GRO/GSO/TSO/LRO on the
configured capture interface. Before capture it reads the original ethtool
state, disables only features that are enabled and mutable, reads the state
again, and aborts a required capture if the disabled state cannot be verified.
After the PCAP process stops, it restores exactly the features changed by the
experiment and verifies restoration.

The full Python application is never elevated. When direct ethtool -K access
is denied, the manager may retry only the exact ethtool command using sudo -n.
Use OFFLOAD_PRIVILEGES.md and scripts/install_offload_sudoers.sh to install a
narrow per-user/per-interface rule. The manifest and proxy summary record the
before/capture/restore states; these diagnostics are not classifier predictors.

-------
<experiment_id>.pcapng
<experiment_id>_packet_sequence.csv
<experiment_id>_fingerprint_sequence.csv

<experiment_id>_manifest.json

The forwarding CSV is diagnostic. Its recv() chunk boundaries are NOT packet
boundaries and must not replace the PCAP-derived packet sequence.

Repairing an earlier broad capture
----------------------------------
If an earlier run captured both proxy legs and the raw packet-sequence CSV is
available, the PCAP is not required for repair:

python3 repair_proxy_sequence.py

The repair utility asks for the participating client IPs, removes packets that
do not involve those clients, recomputes direction, reconstructs TCP flag
bits, and generates clean per-client/windowed fingerprint artifacts.

TLS
---
TLS remains end-to-end between the experiment client and the real server. The
proxy forwards encrypted bytes unchanged.

If certificate verification is enabled on the client and the client connects
to the proxy IP, configure transport.server_hostname on the client to the real
server certificate name.


Automatic client-ID resolution
------------------------------
New federated clients write network_registration ground-truth records with the
actual client_id and source IP. The proxy manifest already records client IPs
and capture trace aliases. Dataset preparation joins those two metadata sources
to resolve the actual federated client automatically.

This mapping is not attacker input. IP addresses, client IDs, and global timing
alignment fields are excluded from the predictor matrix.


v0.8.6 dual inference
---------------------
capture.window_sizes_sec:
  [0.5, 1.0, 2.0, 5.0]

architecture_inference:
  enabled: true
  realtime_enabled: true
  final_enabled: true
  realtime_required: true
  model_root: fingerprinting_models
  feature_modes: [full, size_normalized]
  confidence_threshold: 0.90
  stable_windows: 3

The real-time sidecar observes the same client-facing interface and BPF scope as
the archival capture. It neither terminates TLS nor parses AI payloads. If no
trained bundle is present it emits live network features but no synthetic
prediction.
