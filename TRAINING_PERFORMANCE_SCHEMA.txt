AI FINGERPRINT EXPERIMENT — TRAINING PERFORMANCE SCHEMA v1.2
============================================================

Scope
-----
These files are produced for federated training when performance_logging.enabled=true.
They are ground-truth/system-characterization artifacts and are forbidden as proxy
fingerprinting predictors.

Full-scale round policy
-----------------------
The interactive federated server now defaults to 100 global rounds and rejects values
below 100. Clients never choose the global round count; they receive it from the
server-authoritative FL policy. Scripted/unit-test configurations may still override
this for development.

Client: round_metrics.csv
-------------------------
One row per completed client round. Classification workloads record train_loss,
train_accuracy, train_precision, train_recall and train_f1. Reconstruction workloads
record reconstruction loss/MSE/MAE.

For application=anomaly_detection the client additionally performs held-out anomaly
evaluation after local training. The existing train_accuracy/train_precision/
train_recall/train_f1 fields are populated from that held-out evaluation while
train_loss continues to describe local reconstruction training loss. Additional fields:

anomaly_accuracy, anomaly_precision, anomaly_recall, anomaly_f1, anomaly_auroc,
anomaly_auprc, anomaly_threshold, anomaly_threshold_percentile, anomaly_tp,
anomaly_fp, anomaly_tn, anomaly_fn, anomaly_eval_samples, anomaly_samples,
normal_samples, normal_error_mean, anomaly_error_mean.

Anomaly-specific client files
-----------------------------
For anomaly detection the same round is also written to:
  anomaly_metrics.csv
  anomaly_metrics_<partition>.csv

A concise task-specific result is written to:
  anomaly_detection_metrics.csv
  anomaly_detection_metrics_iid.csv
  anomaly_detection_metrics_non_iid_alpha_<alpha>.csv

The concise file directly contains:
  loss, accuracy, precision, recall, f1_score, auroc, auprc, threshold,
  tp, fp, tn, fn, reconstruction_loss, mse, mae.

Server: client_update_metrics.csv
---------------------------------
One row per received client update per round. In anomaly-detection experiments the
server records the client's anomaly accuracy/precision/recall/F1/AUROC/AUPRC,
threshold and confusion counts in addition to reconstruction metrics and model norms.

Server: round_metrics.csv
-------------------------
One row per completed FedAvg aggregation. For anomaly detection, global_accuracy,
global_precision, global_recall and global_f1 are populated from held-out global
anomaly evaluation. global_loss remains the reconstruction/evaluation loss. AUROC,
AUPRC, threshold and confusion counts are stored in the anomaly_* fields.

Anomaly protocol
----------------
Configured anomaly class labels are excluded from training. Remaining normal examples
are partitioned IID or Dirichlet non-IID across clients. The reconstruction target
remains x -> x. Each round:
  1. The current model scores held-out normal calibration samples by reconstruction MSE.
  2. threshold = configured percentile (default 95th) of normal calibration scores.
  3. A separate held-out normal+anomaly evaluation set is scored.
  4. accuracy, precision, recall, F1, AUROC, AUPRC and confusion counts are computed.

The server distributes anomaly labels and evaluation protocol to clients as part of the
server-authoritative policy. These labels/metrics are never admitted into proxy X.


v0.9.6 classification naming
Multiclass classification additionally records macro_precision, macro_recall, and macro_f1.
Legacy precision, recall, and f1 columns are retained as aliases for compatibility.
Anomaly detection precision, recall, and f1 remain binary positive class metrics.
Server round_metrics.csv records evaluation_time_ms independently from aggregation_time_ms.
Metric CSV rows are flushed and fsynced after every completed write.
