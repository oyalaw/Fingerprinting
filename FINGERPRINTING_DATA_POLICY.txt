AI Fingerprinting Data Isolation Policy
Version 1.1

1. Predictor input X
--------------------
Only proxy-observable network data may enter X.

Allowed sources:
  *_features.csv
  *_fingerprint_sequence.csv

The handcrafted X builder accepts numeric network-derived fields from the
proxy feature CSV. experiment_id, client_capture_id, row_type, and window
identifiers are retained only as metadata for joining/grouped splitting and are
not predictor columns.

2. Ground truth Y
-----------------
Client/server ground-truth logs provide labels only.

Required labels:
  task
  deployment
  framework
  runtime
  family
  architecture
  variant
  application
  device

The client device is used as the device target. The server device is not used
as a target for a client-facing proxy trace.

For federated multi-client runs, client_capture_id in the per-client proxy
feature file must match the exact federated client_id in the client ground-truth
log. Both are grouping/join metadata and are prohibited from the predictor
matrix.

3. Client-facing capture isolation
----------------------------------
An inline proxy creates two TCP legs:

  client <-> proxy
  proxy <-> real server

Capturing both legs duplicates the application byte stream and can invert
semantic direction on the upstream leg. The proxy therefore requires
participating client IPs by default and uses them in the BPF filter. The
upstream proxy-server leg is excluded.

Client IP addresses are used only during capture isolation/grouping and are
removed from classifier-ready packet sequences.

4. Multi-client traces
----------------------
For a multi-client experiment, the combined raw trace is retained for audit,
but model input should use the automatically generated per-client files:

  <experiment_id>__<client_alias>_fingerprint_sequence.csv
  <experiment_id>__<client_alias>_features.csv

The combined multi-client fingerprint sequence is marked classifier-ineligible
in the manifest. prepare_fingerprinting_dataset.py prefers per-client feature
files when they exist.

5. Resource telemetry
---------------------
CPU, GPU, memory, power, energy, process utilization, and other client/server
resource telemetry are prohibited from X. The dataset builder rejects resource
files and rejects resource-like columns if they appear in a proxy feature CSV.

Resource telemetry remains valid for separate performance/system analysis.

6. Packet sequence identity sanitization
----------------------------------------
The raw packet sequence is retained for audit:

  *_packet_sequence.csv

It is NOT classifier eligible because it contains endpoint identity and an
absolute timestamp.

The proxy also emits classifier-safe sequences. They remove:

  timestamp_epoch
  src_ip
  dst_ip
  src_port
  dst_port

They retain packet timing relative to the trace, frame length, direction,
transport protocol, normalized TCP flags, retransmission signal, and observable
TLS record metadata when present.

7. TCP flag normalization
-------------------------
SYN, ACK, FIN, and RST are derived from the tcp.flags bitmask. This avoids
capture-parser version differences where individual tshark flag subfields may
be blank or zero despite the bitmask containing the flag.

8. Capture quality/offload fidelity
--------------------------------------
For packet-size fingerprinting, the proxy manages capture-affecting GRO/GSO/
TSO/LRO on the capture interface by default. It records the original state,
disables enabled mutable features, verifies the capture-time state, stops the
capture before restoration, restores exactly the settings it changed, and
verifies the final state. Required capture fails closed if a safe state cannot
be verified.

The Python application itself is not run as root. Optional non-interactive sudo
fallback is restricted to ethtool -K operations. Interface/offload provenance,
MTU, and oversized-frame diagnostics remain metadata only and are never
predictor labels or automatically injected into X.

9. Windowing
------------
The proxy workflow writes one overall feature row plus 5-second windows by
default. The window length may be changed or disabled. All windows belonging to
the same experiment must remain in the same train/validation/test group.

10. Physical X/Y separation
---------------------------
prepare_fingerprinting_dataset.py produces:

  fingerprinting_X_proxy.csv
  fingerprinting_Y_ground_truth.csv
  fingerprinting_schema.json

X and Y are physically separate. The schema explicitly lists predictor,
metadata, label, and prohibited fields.

11. Strict downstream loading
-----------------------------
ai_fingerprint.fingerprinting_dataset.load_xy() returns only schema-declared
proxy predictor columns as X and one approved ground-truth target as y.
experiment_id, client_capture_id, window identifiers, labels, and resource
metrics cannot enter X through this loader.

12. Local execution
-------------------
Local inference/training does not create workload exchange observable by a
network-side proxy. The proxy dataset builder therefore rejects deployment=local
as a network fingerprinting sample. Local experiments remain useful for
resource/performance baselines or separately defined download/telemetry studies.

13. Splitting
-------------
Do not randomly split packets/windows from the same experiment across train and
test. Split by experiment/run/session/device grouping as appropriate to avoid
leakage.

14. Repair of earlier broad captures
------------------------------------
When the raw *_packet_sequence.csv exists, an earlier broad proxy capture can
be repaired without the PCAP using:

  python3 repair_proxy_sequence.py

The repair process retains only packets involving configured client IPs,
recomputes direction, reconstructs TCP flags from tcp_flags_hex, and produces
clean per-client/windowed classifier artifacts.


15. Client identity resolution
------------------------------
Proxy capture aliases are not assumed to be federated client IDs. New
federated clients log a ground-truth network_registration event containing the
actual client_id and source IP. Dataset preparation joins that source IP to the
proxy manifest's client-IP/capture-trace mapping and resolves the correct
client label out of band. IP addresses and resolved client IDs are never
predictors.

16. Cross-client time alignment
-------------------------------
Per-client feature files may contain trace_start_offset_sec,
trace_end_offset_sec, window_start_global_sec, and window_end_global_sec.
These are alignment/grouping metadata relative to the combined proxy capture,
not predictor columns.

17. Federated Upload semantics
------------------------------
For network-phase ground truth, Upload denotes the client model-send interval.
Waiting after the send for synchronous round release is Idle with
reason=synchronous_round_wait. A separate diagnostic transaction event may
record the total send-plus-wait duration.

18. Encrypted network experiments
---------------------------------
New remote/federated collections should prefer TLS when the study claims
encrypted traffic. The inline proxy remains label-blind and does not terminate
TLS. Plain TCP remains valid for controlled debugging/baseline experiments but
must not be presented as encrypted-traffic evidence.


19. Real-time versus final architecture inference
-------------------------------------------------
Real-time models consume only completed live packet-metadata windows. No future
packets, final experiment totals, client/server resource telemetry, current-run
ground-truth labels, IP identity, or client identity may enter the predictor.

Final models may consume the complete proxy-observable trace after capture
ends. They are trained separately because complete-trace totals are unavailable
to the live model.

20. Multi-scale temporal windows
--------------------------------
v0.8.6 supports 0.5, 1, 2, and 5 second windows by default. window_size_sec is
metadata, not a predictor. Each classifier scale is trained and evaluated
separately.

21. Size-normalized architecture evaluation
--------------------------------------------
The full model represents the realistic attacker and may use absolute traffic
footprint. The size_normalized model suppresses absolute byte, packet, burst,
and transport counts to test whether timing, rates, fractions, packet-size
distributions, and burst morphology retain architecture information.

22. Independent-run evaluation
------------------------------
Windows are correlated observations, not independent experiments. All reported
generalization metrics must split by independent experiment/run groups. Never
randomly place windows from the same run in both training and test sets.


v0.8.9 storage note: the proxy may receive an operator-supplied filesystem storage locator so its outputs can be placed under the same experiment directory hierarchy. The locator is organizational metadata only; it is never copied into packet-sequence or handcrafted-feature predictor columns and is excluded from X.

v0.9.0 TRAINING-PERFORMANCE ISOLATION
--------------------------------------
Per-round learning-performance artifacts are ground truth/system characterization only. The following files and fields MUST NOT enter attacker predictor X:

- client/server round_metrics.csv
- server client_update_metrics.csv
- loss, accuracy, precision, recall, F1
- reconstruction loss, MSE, MAE, KL loss, VAE beta
- global/local/client model norms and update norms
- aggregation/evaluation time and convergence deltas

They may be used to analyze convergence, learning utility, round stability, and correlations after fingerprinting predictions have been produced, but they are not proxy-observable traffic features.
